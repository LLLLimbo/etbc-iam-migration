## Design Context

### Users

The web console is for delivery engineers running a controlled ETBC-to-IAM tenant
migration during a delivery or change window. Their primary jobs are to validate a
source tenant, create an immutable migration snapshot, monitor entity outcomes,
resume incomplete work, and export an auditable final report without exposing
secrets or personal data in the browser.

### Brand Personality

Calm, precise, and accountable. The interface should build confidence through
explicit state, restrained language, and evidence-rich feedback. It should feel
like a carefully made operations instrument rather than a general-purpose admin
dashboard.

### Aesthetic Direction

A light, industrial-utilitarian migration console with warm paper-tinted surfaces,
ink-like text, strong rules, and a restrained safety-orange accent. Information is
dense where operators need evidence, but advanced inputs are progressively
disclosed. The UI is Chinese-first, responsive, keyboard usable, WCAG AA-oriented,
and self-contained with no external fonts, scripts, images, or CDNs.

### Design Principles

1. Make the next safe action unmistakable and require deliberate confirmation for
   IAM writes.
2. Show operational state and immutable identifiers clearly while keeping secrets
   and personal data out of HTML, URLs, browser storage, and logs.
3. Prefer compact evidence over decorative dashboards: counts, timestamps, exit
   states, and sanitized errors should answer what happened and what to do next.
4. Reuse the Python migration core so CLI and web execution have identical
   validation, retry, idempotency, and reporting semantics.
5. Work on delivery laptops and controlled servers without external assets, with
   responsive layouts, visible focus, reduced-motion support, and semantic HTML.
